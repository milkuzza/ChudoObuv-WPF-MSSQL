## Повторная проверка архива от 16.10.2026

После сравнения с «ДЭ-2027-пробный_программист.rar» приложение повторно собрано и проверено на отдельной базе `ChudoObuv_ArchiveTest20261016`. Все 15 групп проверок прошли. Проверка WPF дополнена утверждениями, что менеджер видит список заказов, но не видит элементы изменения даты и удаления отдельной позиции.

Исходный C# отформатирован средствами Roslyn. До и после форматирования сравнены последовательности синтаксических токенов: изменения приложения затрагивают только пробелы и переносы строк. В тестах добавлены снимки входа, совместного поиска и фильтра, а также окна менеджера. Все семь иллюстраций руководства получены из WPF-форм, связанных с данными тестовой MSSQL; даты и остатки после испытаний сверены с исходными значениями.

Руководство пользователя создано из предоставленного шаблона старого формата DOC, преобразованного в DOCX через установленный Microsoft Word. Тем же Word обновлены оглавление и число страниц и экспортирован PDF. Проверены все 14 страниц, семь иллюстраций, номера разделов и отсутствие незаполненных текстов шаблона.

## Повторение

В PowerShell из корня решения:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1 -Tests
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Initialize-Database.ps1 -Database 'ChudoObuv_WpfVerification'
$env:CHUDOOBUV_TEST_CONNECTION_STRING = 'Data Source=(LocalDB)\MSSQLLocalDB;Initial Catalog=ChudoObuv_WpfVerification;Integrated Security=True;Connect Timeout=15'
.\ChudoObuv.Tests.exe
```

Ожидаемый результат: `All 15 checks passed against ChudoObuv_WpfVerification`. Нужна свежая база с исходными данными; после успешного прогона проверки возвращают исходные количества и удаляют созданные заказы. Идентификаторы IDENTITY могут иметь пропуски — это нормальное поведение SQL Server при откате транзакций.

Тестовый запуск отказывается работать с базой, в имени которой нет `Verification` или `Test`. При прерванных испытаниях используйте другое новое имя тестовой базы и укажите его в переменной окружения.

Проверка защиты импорта: повторите `Initialize-Database.ps1` для уже подготовленной базы. Скрипт должен сообщить `Database ready` и сохранить данные. Полный `database_with_data.sql` при повторном выполнении должен сообщить о существующих таблицах, не добавляя дубликаты.

## Ручная проверка

1. Открыть `Launch.cmd`, проверить каталог гостя и карточку товара.
2. Войти как покупатель, применить поиск, категорию и сортировку; добавить два размера разных моделей.
3. Открыть корзину, изменить количество, удалить позицию, продолжить выбор, подтвердить заказ.
4. Войти как менеджер, проверить состав заказа и оформление на выбранного клиента.
5. Войти как администратор, изменить дату, удалить позицию, проверить итог и возврат остатка.
6. Удалить созданный заказ; убедиться, что исходные остатки вернулись.

## Границы проверки

Проверена конфигурация LocalDB и Windows Authentication. Для удалённого экземпляра SQL Server необходимы доступная сеть и выданные пользователю права. Готовый EXE собран `Build.ps1`. При проверке системным MSBuild без Targeting Pack использованы установленные сборки Framework; для разработки в Visual Studio установите .NET Framework 4.8 Targeting Pack, как указано в инструкции. Оплата и последующая обработка заказа в задании не предусмотрены. Вход без пароля реализован по условию учебного задания; доступ к самой базе защищается учётной записью SQL Server/Windows.
